# 评测与拒答：建立可以解释的质量账本

编号：ai-05 · 年底核心 · 学习预算 6 小时

把正确回答、错误引用和应该拒答的情况放进同一张可追踪记录。

## 学习目标

- 建立问题与原句证据的对应
- 区分检索、回答、引用和性能指标
- 解释开发集与测试集的用途

建议先修：[ai-04](ai-04.md)

## 先定义什么叫完成客户任务

客户说“回答准确”还不足以验收。需要进一步确定问题范围、资料有效日期、可接受的回答粒度、引用必须到页还是段，以及找不到证据时怎样回应。把这些要求变成具体问题与参考证据：普通事实题、需要两个片段的题、旧规则与新规则冲突题、无答案题、容易混淆的编号题。参考答案应来自原文和明确的人工判断，不直接用被测模型给自己出标准答案。先做十条高质量题，也比收集几百条没有出处的问题更能定位工程缺口。

## 拆开指标，避免一个分数遮住原因

检索层看相关证据是否进入候选；回答层看关键事实、条件和遗漏；引用层看来源是否真实存在且实际支持对应断言。格式合法率和HTTP成功率也要记录，但它们不代表上述质量。OCR中的CER按字符插入、删除和替换计算，对格式与关键字段的敏感性不同；表格还需检查行列关系。性能层分别记录完整响应耗时、首内容延迟、用量和失败，不把缺失值写成零。一个答案可以事实正确却引用错误，必须允许评测表把这两件事分开标注。

## 拒答是正常行为，不是系统坏了

当资料没有答案、来源冲突、权限不够或证据质量不足时，系统应说明具体缺口，并在合适时请求补充。不能用很低的检索分数阈值覆盖所有情况，因为分数随模型和语料变化。可以结合来源有效性、必要字段、任务边界与人工规则。无答案题要同时观察误答率和可回答题的误拒率；若系统对所有问题都说不知道，虽然少编造，却不能满足业务。把回答与拒答看成同一个决策的两种结果，评价时报告二者的取舍，而不是只统计成功回答。

## 多轮问题先还原检索意图，再核对回答依据

用户上一轮问“设备维修工单由谁审批？”，这一轮只问“那它要多久？”。直接检索后一句会缺少对象；可以从最近相关、仍有效的用户消息中取回主题，将独立检索问题改写为“设备维修工单审批需要多长时间？”。这里补回的是对话已明确的对象，不是答案；不能自行改成“为什么需要三个工作日”，因为历史没有确认这个时长。上一轮模型的回答也可能出错，不能把它提出的期限或审批人当成已验证事实继续传播。

保存三类记录：原问题 original_question、用于消解指代的历史轮次及原文 history_evidence、独立问题 rewritten_question；另外记录改写版本与是否需要澄清。只取必要的相关历史，避免无关对话、过期规则和长日志进入检索输入；每次仍按当前用户权限检索。若最近同时讨论维修审批和GPU预约审批，“它”有两个合理对象，应先询问用户指哪一种，不替用户猜。检索拿到证据后再回答原始意图；仍无期限说明就明确缺少依据。评测加入“可明确改写”和“有歧义需澄清”两个案例，分别检查对象、条件、范围是否保留，并把改写错误与召回错误分开记录。

## 开发、验证和测试承担不同职责

开发集用于发现问题、调整切分、提示和阈值；验证集帮助在方案间选择；最终测试集在方案固定后检查泛化。若反复根据测试集错误修改系统，这组题已经变成开发或回归数据，应如实更名。文档同一段改写成十个相似问句再随机分组，仍可能发生信息泄漏。按来源、主题或时间分组能更贴近真实变化，但也要说明划分是否符合业务。保存题集版本、语料摘要、模型配置和代码提交，才能判断两份报告是否具有可比性。

## 让报告保留失败，也支持回归

每条记录包含问题ID、参考来源、候选片段、最终上下文、答案、引用、耗时、状态与判定理由。自动规则适合检查编号、字段和范围，模型裁判可以辅助筛查，但二者都有误差，重要样本需要人工核对。改动后先重跑受影响的问题，再用固定回归集确认没有破坏原先正确的案例。小样本结果应写清分母，不把8/8合成字段覆盖包装成企业文档准确率。交付时展示一个典型失败及修复证据，通常比只展示最漂亮的一条回答更能说明系统是否可维护。

## 本课具体例子

```python
cases = [
 {"id": "q1", "answerable": True, "answered": True, "grounded": True},
 {"id": "q2", "answerable": False, "answered": True, "grounded": False},
 {"id": "q3", "answerable": False, "answered": False, "grounded": True},
]
unknown = [x for x in cases if not x["answerable"]]
false_answers = sum(x["answered"] for x in unknown)
print({"unknown_questions": len(unknown),
       "false_answer_rate": false_answers / len(unknown)})
```

Python 3标准库。标签是人为构造，不是模型实测；本例无答案误答率为1/2。

配套实验：[labs/ai_retrieval.py](../labs/ai_retrieval.py)。请在解压包根目录按脚本说明运行。

## 本课只做一个任务

从一页文档编写五条带证据的问题，其中至少两条应拒答。

1. 先圈出原文事实和不包含的信息。
2. 记录问题、参考原句、可回答性与关键条件；其中一题采用多轮追问，另存原问题、相关历史与独立检索问题。
3. 选一题说明自动规则可能怎样误判。

### 验收

- 五题都有明确判断依据
- 至少一条展示规则误判边界
- 数据标注与模型输出分开保存
- 多轮题可追溯改写依据，未凭空补事实；歧义有明确处理

需要保存：保存本课输入、运行或审阅结果、你的解释与尚未解决的问题。

## 失败时检查

### 分数提高但客户仍不满意

可能原因：指标未覆盖真实条件或拒答代价

检查：回到客户任务检查题集

### 测试集满分却新文档差

可能原因：重复调参或来源泄漏

检查：按来源与时间审阅划分
