# 从 OCR 到可追踪文档：清洗、分块与版本

编号：ai-03 · 年底核心 · 学习预算 6 小时

保留原始证据，让检索结果能回到真正的页面。

## 学习目标

- 区分原文件、解析文本和检索片段
- 给片段保留来源与版本
- 解释分块长度与边界的取舍

建议先修：[ai-02](ai-02.md)

## 文档入口先回答“拿到了什么”

同一个PDF可能同时含可提取文字、扫描图片、双栏排版与表格。先记录文件类型、字节大小、页数、文件摘要和来源，再决定直接提取还是栅格化后OCR。OCR模型处理的是准备后的图像；旋转、缩放、颜色转换会改变输入，因此要记录处理参数。解析完成只表示服务返回了结果，不意味着编号、金额或行列关系正确。像I与l、0与O这类近似字符，整体错误率很低仍可能改掉关键标识。对业务关键字段应单独核验，不能只看一张总分卡片。

## 清洗不能把证据擦掉

保留原始输出，再生成清洗版本。可以统一换行、去掉明确重复的页眉，但应对每条规则写例子和反例。全局删除所有数字可能消除页码，也会抹掉日期和型号；把表格每行拼成段落，可能丢失列名与数值的对应。清洗记录包括规则版本、输入输出摘要及变更原因。文档中出现“忽略前面指令”仍是被解析的数据，不能因为它被模型读到了就提升为系统指令。对HTML表格先按文本或受限结构查看，不把任意模型输出直接当网页执行。

## 分块是在预算与语义之间取舍

片段太大容易混入无关内容并占满上下文，太小可能把条件、例外与主句拆散。先沿标题、段落或表格结构切分，再在超长时使用有界窗口；重叠可以保留边界语境，也会增加存储与重复召回。每块应带document_id、版本、页码、段落位置和chunk_id。不要声称只保留Markdown就自动保留了原PDF坐标。若要高亮原图，需要另存坐标映射。第一轮只取一页通知，检查问句所需的条件是否与答案处于同块，再调长度。

## 版本决定一次更新会影响什么

文件内容摘要用于检测字节变化，稳定来源ID用于识别“同一份文档的新版”，两者不能互相替代。上传相同文件可以复用已有结果；同一文档内容变化则应产生新版本，并记录旧版本如何失效。索引更新前后要能判断哪些片段被新增、替换或删除。若只追加新片段不处理旧片段，查询可能同时拿到互相冲突的制度。引用里保留原文件版本和索引版本，能帮助区分模型答错与系统检索到过时材料。删除原文件也要考虑派生文本、向量和缓存的生命周期。

## 把两套系统的接口真正接起来

DocLens能导出逐页结果，知识库能接收文本，中间仍需编写适配层：选择成功页、校验内容、生成来源字段、提交目标接口并保存两边ID。重复导入应返回已有映射，失败要记录发生在解析、上传还是索引阶段。部分页面失败时，不要把整份文件标成全部成功；成功页是否允许单独发布应由业务规则决定。以同一页导入两次但索引只有一份、且能回到OCR任务作为首个验收，比把整目录一次上传更容易解释。当前课程提出这条链路，不把尚未实现的自动接入写成已有功能。

## 本课具体例子

```python
import hashlib
text = "## GPU申请\n使用前提交用途与时间。\n"
record = {"document_id": "notice-001", "version": 1, "page": 1,
          "chunk_id": "notice-001:v1:p1:c1", "text": text,
          "content_sha256": hashlib.sha256(text.encode()).hexdigest()}
print(record["chunk_id"], record["content_sha256"][:12])
```

Python 3标准库，构造一条教学来源记录；未导入真实索引。

## 失败时检查

### 引用找不到原图位置

可能原因：只保存了文本块

检查：检查是否实际保存页码/坐标映射

### 同一问题返回新旧制度

可能原因：增量写入未失效旧版本

检查：按document_id和版本检查索引
