## 先定义规模和需要的操作

设n为输入文档数，k为不同文档数，m为总字符数，它们不能混用。按标题去重与按全文哈希去重的代价不同：前者比较短键，后者至少读取m个字符。Python列表适合按下标取元素和尾部追加，在头部插入通常需要移动后面的元素；链表按序号寻找节点要顺着链接走，不能因为插入容易就断言整体更快。为任务队列选择deque，是因为头尾操作适合该访问方式。复杂度描述随规模增长的趋势，不直接等于某台机器的秒数，也不会自动包含网络和磁盘等待。

## 哈希集合保成员关系，列表保顺序

保持首次出现顺序去重时，用seen记录已经遇到的键，用result记录输出顺序。若每次在result列表里查找，单次可能遍历已有元素，最坏整体接近平方增长；集合成员查找在常见假设下平均接近常数，因此整体平均线性。还要记住哈希碰撞、扩容和键本身的哈希代价，不能把平均说成无条件最坏保证。栈后进先出适合撤销和DFS的待访问节点，队列先进先出适合BFS层次扩展。结构只是表达处理规则，任务优先级和公平性还需要明确的业务约定。

## 排序、二分和窗口都有前提

二分查找依赖有序输入或单调判断条件，每轮排除一半候选。寻找第一个不小于目标的位置时，应写清左闭右开的区间约定，尤其测试空数组、重复值和目标不存在。先排序再查一次的总成本包含排序；若以后反复查询，预处理才可能划算。双指针适合某些有序配对问题，滑动窗口适合维护连续区间的增量状态，但不能把所有连续区间题都机械套模板。允许负数的求和条件可能破坏窗口单调性。每种算法先写成立条件，再写代码，才能解释它什么时候失效。

## 树、堆和图对应不同关系

目录可表示为树，二叉树只是每节点最多两个子节点的一类树；文档互相引用会形成图，可能有环。BFS适合无权图最少边数，带非负权的最短路可考虑Dijkstra，负权场景需换方法。堆适合反复取当前最小优先级，但不保证整个数组有序。遍历图时记录visited避免循环，文档依赖若有环就不能直接当树递归。递归需要结束条件和进度变量，也要考虑调用栈限制；动态规划则识别重复子问题，存储中间答案，常可把指数级重复计算变为受控的状态遍历。

## 用对照输入验证推理，不靠背结论

阅读TheAlgorithms时先看函数的输入约束和示例，再画两轮状态变化。为同一任务保留朴素版本与改进版本，在小规模上比较结果一致性，用独立计数器统计比较次数，避免把毫秒级噪声当复杂度证据。空输入、全部重复、极端排序和缺失目标往往比随机样本更能暴露边界。本课只实现顺序去重并分析平均时间和额外空间；树与图作为后续阅读入口，不要求一口气写完整算法库。能说清为什么某个前提必须成立，比记住一个O符号更可迁移。

## 保持首次出现顺序的去重

```python
def ordered_unique(values):
    seen = set()
    result = []
    for value in values:
        if value not in seen:
            seen.add(value)
            result.append(value)
    return result

print(ordered_unique(["SQL", "API", "SQL", "HTTP"]))
print(ordered_unique([]))
```

Python 3.9+；适用于可哈希元素。输出保留SQL、API、HTTP，平均时间O(n)，额外空间O(k)，不适用于直接作为键的可变字典。

## 失败时检查

### 去重后顺序变化

可能原因：把集合的迭代顺序当业务顺序

检查：显式维护结果列表。

### 二分返回错误边界

可能原因：输入未排序或区间约定混乱

检查：逐轮写lo、hi、mid及不变量。
