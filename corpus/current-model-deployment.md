# 当前混元模型部署状态

资料日期：2026-11-15。本文描述本次迁移后的现行部署；涉及当前模型、GPU 和训练适配器时优先于此前 Qwen 基线资料。旧基线资料保留用于历史实验对照。

## 当前模型与端口

当前在线生成模型为 tencent/Hunyuan-1.8B-Instruct。模型目录是 /home/learner/test/models/Hunyuan-1.8B-Instruct。

唯一 GPU 模型服务监听 127.0.0.1:18301，提供 OpenAI 兼容的 POST /v1/chat/completions。知识库页面在 18300，旧学习工作台在服务器 18200。

18123 现在是 CPU 兼容代理，保留 POST /generate 和 POST /generate/stream，将请求转发到同一个混元实例；它不再独立加载千问模型，也不占用模型显存。

## 共享 GPU 预算

混元仅使用物理 GPU 0。部署目标是单卡 8–10 GiB 显存预算，上下文上限 2048 token，同时执行序列数为 1。GPU 1 不运行本项目的常驻生成模型。具体显存以 nvidia-smi 实时采样为准。

显存预算不是 GPU 算力配额；短时请求仍可能出现高计算利用率。停止学习模型服务才能释放常驻显存，删除权重文件主要释放磁盘。

## 历史训练与当前限制

incident-triage 是以前基于 Qwen2.5-3B 训练的 LoRA，不能直接加载到混元。历史训练曲线、数据、适配器和报告继续保留，但当前在线工单实验只能选择混元基础模型。

本次仅完成混元推理与接口迁移，没有完成混元微调。新结果与历史 Qwen 结果必须分别标记模型、计时口径和测试配置。

## 启停自己的模型

在服务器运行 systemctl --user stop fde-vllm 可停止本项目混元模型并释放其显存；运行 systemctl --user start fde-vllm 恢复。页面与学习资料仍可阅读，但模型停止期间实时生成不可用。
