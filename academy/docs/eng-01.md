## 先说清函数接收什么、返回什么

把“写个文本处理程序”缩小为一个契约：输入一段字符串，返回按空白分开的片段数。变量名content代表一个对象的引用，str说明约定的类型，return把结果交还调用方。列表用于保留顺序，字典用键表达字段，集合用于成员判断；结构的选择应跟访问方式有关。函数只完成一个容易描述的职责，才能判断错误发生在输入、计算还是保存。先手算空字符串、连续空格和中文连续句子的结果，再执行代码。这样你在学习语言时已经同时练习定义验收，而不是只照抄输出。

## 类型提示和运行时检查是两件事

def count_words(content: str)并不会在调用入口自动禁止整数。普通Python解释器主要根据实际操作执行，整数没有split方法，错误可能到下一行才出现。静态类型检查工具能提前指出一部分不匹配；对外API还需要运行时校验，把不合格输入映射为可理解的响应。不要为了让程序不报错就把所有输入都str化：None会变成字符串None，含义已经变化。校验应说明允许的类型、长度与空值语义。对于返回字典，也要分清字段缺失、字段为null和空字符串，它们在业务协议中可能代表三种不同状态。

## 异常沿调用链传播，处理者要知道恢复办法

发生异常后，当前正常路径停止，解释器向上寻找匹配的except。你可以在数据读取层补充路径背景，再把异常交给API映射；也可以在最外层记录一次失败。只有知道怎样恢复时才吞掉异常，例如可选配置不存在时使用明确默认值。except Exception后返回空列表，可能把“数据读取失败”伪装成“没有数据”，让后续评测给出错误结论。保留原始异常类型、调用栈与脱敏上下文，避免在每一层重复打印。finally用于不论成功或失败都应做的清理；它不代表业务成功，也不应该随意return覆盖原始异常。

## 文件、连接和锁都有申请与释放

open获得的不只是Python对象，还关联操作系统文件描述符。with open(...)让退出代码块时执行关闭，异常路径同样有清理机会；手动打开则需要try/finally。上下文管理器封装的是进入和退出约定，数据库连接的with行为要看具体库，不能从文件的行为推断。装饰器也是包装或注册行为的一种方式：@router.post通常把函数登记为路由，不意味着函数自动执行。先定位包装增加了什么，再理解原函数做什么。把申请、使用、释放画成三格，能帮你发现循环里反复开连接却不关的泄漏。

## 环境和可变状态是复现的基础

python与python3可能指向不同解释器，虚拟环境隔离的是项目依赖而非整台操作系统。记录python --version和sys.executable，再用该解释器执行python -m pip，避免安装到甲环境却在乙环境运行。列表和字典可变：两个变量引用同一列表时，一方修改会被另一方看到；默认参数写成[]还可能让多次调用共享状态。将状态显式传入，必要时复制，并用两个连续调用验证是否互相影响。本课交付不是一张运行成功截图，而是输入约定、边界输出与资源清理位置的解释；这些基础会直接影响后续文档解析和任务服务。

## 按空白统计，并验证边界

```python
def count_words(content: str) -> int:
    if not isinstance(content, str):
        raise TypeError("content must be str")
    return len(content.split())

for text in ["", "hello\nagent", "你好世界"]:
    print(repr(text), count_words(text))
```

Python 3.9+标准库即可运行；结果依次为0、2、1，最后一个不是中文分词结果。

## 失败时检查

### 安装后仍ModuleNotFoundError

可能原因：安装和执行使用不同解释器

检查：对比sys.executable，并使用同一解释器的-m pip。

### 错误输入变成空结果

可能原因：异常被宽泛捕获并吞掉

检查：查except分支，保留异常类型和失败状态。
