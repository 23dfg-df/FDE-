# 从小模型训练到微调产物交付

本章从一个只有 3 个可训练参数的 CPU 分类器开始。先亲自完成“训练、验证选模型、保存、退出进程、重新加载、预测”，再阅读已有 Qwen 工单微调代码，最后判断迁移到混元还缺什么。

**当前项目状态：Hunyuan-1.8B-Instruct 已用于推理；混元微调尚未实现或验收。** `training/experiment.py` 属于历史 Qwen2.5-3B 实验。本章的 CPU 入门不需要 GPU，不下载任何大模型，不必停止现有推理服务。

建议分两次学习：第一次完成第 1—4 节的小实验，第二次阅读第 5—8 节并做源码核对。每次只提交一项自己的解释，先读懂结果再进入下一节。

## 1. 先判断：什么操作真的改变了模型

先做一道判断题：向模型发送 100 条问题、修改系统提示、向知识库添加文档、反向传播并更新参数，分别改变了什么？先在笔记里写答案。

提示：区分“本次请求的输入”“外部可检索资料”“保存下来的模型参数”。本项目的 `/api/ask` 会调用推理服务，不会替你执行训练。

<details>
<summary>完成后查看解释</summary>

发送问题会产生输出和运行记录；修改提示会改变输入；新增文档并重建索引会改变检索内容。这三者都不必修改模型权重。训练则用目标答案计算损失、求出参数梯度，再按优化规则更新允许训练的参数。微调是在已有权重上继续做这种更新。

</details>

一次监督训练可以拆成下面这条链。自动微分库能代算梯度，但不会替你判断数据是否合理。

```text
训练样本和标签 → 前向计算 → 损失 → 梯度 → 优化器更新参数
                                  ↑          │
                                  └─ 下一步 ─┘
验证集 → 只做前向计算 → 比较候选模型
冻结选定模型 → 最终测试 → 保存 → 新进程加载 → 推理验收
```

| 术语 | 在本章小实验中的含义 | 最容易混淆的点 |
|---|---|---|
| 参数 | 两个特征的权重和一个偏置，共 3 个数 | 学习率是人设定的超参数，不是这 3 个权重 |
| 损失 | 预测概率与真实二分类标签的差异度量 | 损失下降不一定让正确分类的样本数立刻增加 |
| 梯度 | 当前损失对参数变化的局部敏感程度 | 它不是“正确答案与预测的文本差” |
| 学习率 | 每次沿负梯度方向移动的步长系数 | 太大可能震荡，太小可能很慢；没有通用最优值 |
| step | 本例中一次完整训练集梯度更新 | 大模型脚本中一次 step 可能包含多个微批次 |
| checkpoint | 某一时刻模型状态的保存产物 | 只存推理权重，不一定足以无缝恢复训练 |

把这一链条对应到 PyTorch 时，常见顺序是清空旧梯度、计算损失、`backward()`、`optimizer.step()`。本章手写简单梯度，让你看见究竟更新了什么；PyTorch 训练循环可继续阅读[官方优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)。

## 2. 训练、验证和测试各自负责什么

本例用固定随机种子生成 600 个**完全虚构的教学样本**，每个样本有两个数值特征与一个 0/1 标签。标签按概率抽样，因此数据并非保证可完美分类；它不代表真实工单、医学判断或业务数据。

| 划分 | 样本数 | 本例是否更新参数 | 用途 |
|---|---:|---|---|
| train | 400 | 是 | 计算梯度；拟合特征归一化所需的均值和标准差 |
| validation | 100 | 否 | 每 10 步检查损失，选择验证损失最低的权重 |
| test | 100 | 否 | 选好模型后评估一次，再用于检查保存重载一致性 |

先预测两个问题：为什么不能用所有 600 个样本计算归一化均值？为什么不能根据测试分数选学习率？

<details>
<summary>完成后查看解释</summary>

归一化也是从数据中拟合出的处理规则。如果提前让测试数据参与，就让原本留作独立检查的信息进入了训练流程。用测试分数反复挑学习率也会把测试集变成调参依据。两种做法都可能让最后报告过于乐观。本例只从训练集计算均值和标准差，再原样用于验证、测试及部署。

</details>

固定随机种子有助于复做，不保证跨 NumPy 版本、硬件和实现的输出逐位一致。记录环境和容差比只记录 seed 更完整。若后续用本例测试集反复比较超参数，应称它为回归样本，并另留新的最终测试集。

### 3.2 训练并保存

模型先算分数 `z = X @ weights`，再经 sigmoid 转为类别 1 的概率。代码最后给每个样本附加常数 1，因此 `weights` 的最后一个数就是偏置。

单个样本的二分类交叉熵为 `-[y·log(p) + (1-y)·log(1-p)]`。本例取训练样本的平均值；相应梯度为 `X.T @ (p-y) / N`。因此更新语句是在用整批样本的平均梯度改变这 3 个参数。代码用等价的 `logaddexp(0, z) - y*z` 计算损失，减少直接对接近 0 的概率取对数带来的数值问题。

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv-ci/bin/python - <<'PY'
import csv
import json
import os
import platform
from pathlib import Path
import numpy as np

run = Path(os.environ["FDE_TINY_RUN"])
rng = np.random.default_rng(42)
raw = rng.normal(size=(600, 2))
true_probability = 1 / (1 + np.exp(-(1.8 * raw[:, 0] - 1.2 * raw[:, 1] + 0.3)))
labels = (rng.random(600) < true_probability).astype(np.float64)
order = rng.permutation(600)
train_ids, val_ids, test_ids = order[:400], order[400:500], order[500:]
mean = raw[train_ids].mean(axis=0)
scale = raw[train_ids].std(axis=0)
scale = np.where(scale > 0, scale, 1.0)

def features(values):
    normalized = (values - mean) / scale
    return np.column_stack([normalized, np.ones(len(values))])

def probability(matrix, weights):
    return 1 / (1 + np.exp(-np.clip(matrix @ weights, -50, 50)))

def loss(matrix, targets, weights):
    logits = matrix @ weights
    return float(np.mean(np.logaddexp(0, logits) - targets * logits))

train_x, val_x = features(raw[train_ids]), features(raw[val_ids])
train_y, val_y = labels[train_ids], labels[val_ids]
weights = np.zeros(3)
learning_rate = 0.1
history = []
best_loss, best_step, best_weights = float("inf"), 0, weights.copy()
for step in range(301):
    if step % 10 == 0:
        train_loss = loss(train_x, train_y, weights)
        val_loss = loss(val_x, val_y, weights)
        if not np.isfinite([train_loss, val_loss]).all():
            raise RuntimeError("损失不是有限值，停止并检查计算")
        history.append([step, train_loss, val_loss])
        if val_loss < best_loss:
            best_loss, best_step, best_weights = val_loss, step, weights.copy()
    if step < 300:
        gradient = train_x.T @ (probability(train_x, weights) - train_y) / len(train_y)
        weights -= learning_rate * gradient

# 测试集不参与上述更新或模型选择。
test_x = features(raw[test_ids])
test_probability = probability(test_x, best_weights)
test_accuracy = float(np.mean((test_probability >= 0.5) == labels[test_ids]))
np.savez(run / "model.npz", weights=best_weights, mean=mean, scale=scale)
np.savez(run / "reload-check.npz", raw=raw[test_ids], labels=labels[test_ids],
         expected_probability=test_probability)
with (run / "curve.csv").open("w", newline="") as handle:
    writer = csv.writer(handle)
    writer.writerow(["step", "train_loss", "validation_loss"])
    writer.writerows(history)
summary = {"source": "synthetic_teaching_data", "seed": 42,
           "python": platform.python_version(), "numpy": np.__version__,
           "split_counts": {"train": 400, "validation": 100, "test": 100},
           "learning_rate": learning_rate, "updates": 300,
           "selected_step": best_step, "selected_validation_loss": best_loss,
           "test_accuracy": test_accuracy, "trainable_parameters": 3}
(run / "summary.json").write_text(json.dumps(summary, indent=2) + "\n")
print(json.dumps(summary, indent=2))
print("已保存；本训练进程即将退出。")
PY
```

### 3.3 在另一个 Python 进程中重载

下面这次命令会启动新的 Python 进程，不复用前一进程的变量。它只从文件读取权重与预处理参数；`reload-check.npz` 是验收样本，不是部署模型的一部分。

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv-ci/bin/python - <<'PY'
import json
import os
from pathlib import Path
import numpy as np

run = Path(os.environ["FDE_TINY_RUN"])
with np.load(run / "model.npz", allow_pickle=False) as saved:
    weights, mean, scale = saved["weights"], saved["mean"], saved["scale"]
with np.load(run / "reload-check.npz", allow_pickle=False) as check:
    raw, labels, expected = check["raw"], check["labels"], check["expected_probability"]
matrix = np.column_stack([(raw - mean) / scale, np.ones(len(raw))])
probability = 1 / (1 + np.exp(-np.clip(matrix @ weights, -50, 50)))
max_difference = float(np.max(np.abs(probability - expected)))
if not np.allclose(probability, expected, rtol=0, atol=1e-12):
    raise RuntimeError(f"重载结果不一致，最大差异 {max_difference}")
report = {"reload_matches": True, "max_probability_difference": max_difference,
          "test_accuracy": float(np.mean((probability >= 0.5) == labels)),
          "predictions_checked": len(labels)}
(run / "reload-result.json").write_text(json.dumps(report, indent=2) + "\n")
print(json.dumps(report, indent=2))
PY
```

`np.savez` 把多个命名数组保存进一个 NPZ 文件，读取时按键取回。本例保存的均为数值数组，因此重载可明确使用 `allow_pickle=False`；保存行为见 [NumPy 官方说明](https://numpy.org/doc/stable/reference/generated/numpy.savez.html)。

</details>

### 3.4 怎样才算完成

终端应该给出实际 `selected_step`、验证损失、测试正确率与重载检查结果；这些数值由你运行产生，本章不预先承诺准确率。核对输出目录中是否有下列产物：

| 产物 | 用途 | 不能由它单独证明什么 |
|---|---|---|
| `curve.csv` | 画训练与验证损失曲线；可用表格软件打开 | 不能证明未知业务问题答得好 |
| `model.npz` | 预测所需的权重、均值和标准差 | 不能无缝恢复所有训练状态 |
| `summary.json` | 解释参数、划分、所选步和最终分数 | 不能替代逐样本错误分析 |
| `reload-check.npz` | 保留固定输入与训练后预测用于一致性检查 | 不是新增的独立泛化测试集 |
| `reload-result.json` | 验证新进程得到相同预测 | 不能证明模型比基线更有效 |

验收要求是：数据划分符合预期、损失始终有限、选中的确是记录中验证损失最低的步、权重已保存、新进程重载通过。准确率是否足够高要由任务目标另行定义，不应把“必须 100%”当成本实验通过条件。

## 4. 用曲线诊断问题，而不是只看最后一个数字

先打开 `curve.csv`，横轴选择 `step`，纵轴放 `train_loss` 和 `validation_loss`。学习率、数据版本、划分和模型都保持不变时，才能讨论某个设置造成的差别。

| 观察到的现象 | 可以提出的假设 | 下一步怎样验证 |
|---|---|---|
| 两条曲线都缓慢下降 | 模型正在学习，或学习率较小 | 延长训练只在训练/验证集上判断；不要同时改多个参数 |
| 训练下降，验证反而上升 | 可能开始过拟合，也可能验证样本少 | 对照最佳验证步，检查错误样本和划分，不能只截取好看的区间 |
| 损失下降但正确率不变 | 概率改变但没跨过 0.5 决策阈值 | 查看同一批预测概率，而不只看0/1结果 |
| 新进程预测不同 | 权重、预处理、精度或输入有漂移 | 先逐项核对保存数组与输入；不要立即归因于模型不稳定 |
| 模型重新加载后似乎“变差” | 可能用错了标准化参数 | 对照训练集的 `mean`/`scale`，不能在每批新输入上重新拟合 |

**下一次小练习：** 只在本次运行目录的副本中修改保存的一个归一化参数，再重载，确认一致性检查能发现变化。原始产物保留，记录“坏了什么、哪项检查发现、怎样恢复”。

## 5. 从 3 个参数过渡到 LoRA 与 QLoRA

全参数微调会更新允许训练的完整模型权重；LoRA 冻结相应的原始矩阵，用两个较小矩阵表达增量。对一个形状为 `d_out × d_in` 的线性层，可写成：

```text
原输出：y = W x
LoRA： y = W x + (alpha / r) B A x
A 的形状：r × d_in；B 的形状：d_out × r
仅这两个矩阵的可训练参数：r × (d_in + d_out)
```

例如**纯算术示意**中，`d_in = d_out = 4096`、`r = 8`，原矩阵有 16,777,216 个参数，增量两矩阵共有 65,536 个参数。这不是本项目混元实际模块形状或适配器参数量。真实统计应遍历被选中的模块，考虑偏置、额外保存层和具体 LoRA 变体。此处是标准 LoRA 缩放；不同变体可能采用不同规则。[PEFT LoRA 参数说明](https://huggingface.co/docs/peft/v0.17.0/package_reference/lora)。

QLoRA 把冻结基座以低比特形式存放，并训练 LoRA 增量。历史脚本使用 NF4、双重量化与 BF16 计算；“4-bit”不意味着每个计算、梯度和优化器状态都只占 4 bit。[PEFT 量化说明](https://huggingface.co/docs/peft/v0.17.0/en/developer_guides/quantization) 与 [QLoRA 原论文](https://arxiv.org/abs/2305.14314) 描述了这种组合。

| 显存组成 | 为什么训练时仍然需要 |
|---|---|
| 基座权重和量化元数据 | 前向与反向仍要经过冻结模型，且量化缩放信息有额外开销 |
| 可训练参数、梯度、优化器状态 | LoRA 参数少，不代表这三类状态不存在 |
| 中间激活与计算工作区 | 需要对可训练部分求梯度；长度和微批次会影响峰值 |
| 临时张量与运行时预留 | 框架缓存、算子实现、内存碎片都会影响观察值 |

`参数量 × 每参数字节数` 只能估计某一项权重存储，不能作为总训练显存承诺。历史脚本要求启动时至少 10 GiB 空闲，只是预检门槛；它不证明所有序列长度、batch 或共享负载都能成功。先完成 CPU 入门，再单独安排训练资源窗口。

| 源码位置 | 你要追踪的状态变化 | 核对问题 |
|---|---|---|

| `validation_loss` | 按有效答案 token 数加权验证损失 | 为何不是随意平均长短不一的样本损失？ |
| `evaluate` / `score_answer` | 测试生成与四项规则判断 | 正确类别但错误下一步动作，应算哪个指标通过？ |
| `worker(..., stage="reload")` | 训练进程结束后，从磁盘重建基座和适配器 | 比较的是20个答案文本，还是所有浮点参数？ |

历史配置为 batch size 1、梯度累积 4、学习率 0.0002、默认 80 次优化器更新；代码只接受 60—100 步。因此一个 optimizer step 汇集 4 个微批次梯度，不能把“80步”直接解释成“80个epoch”。训练集迭代完会重新打乱继续取样。

标签中的 `-100` 是让损失计算忽略对应位置的标记，不是要模型生成的 token。提示仍在输入中，为回答提供条件；本脚本只监督后续答案部分。若全部有效答案都被截掉或屏蔽，就没有正确的学习目标，这也是脚本拒绝超长完整标签的原因。

脚本先在同一量化精度和零增量 LoRA 条件下测基线，再训练、评测并保存；测试问题前后固定。它每10步及最后一步测验证损失，其他曲线点为 `null`，不能画成0。该历史脚本没有按最低验证损失回滚选模型，不能把本章小模型的选择逻辑误套给它。

四项指标分别是严格 JSON 格式、类别、下一步动作和联合通过率。格式错误也必须留在分母中。下一步动作只是分类标签，不代表服务器真的执行过检查；评测不能把模型输出的指令视为已执行动作。

## 7. 训练完成、可重载与可部署，是三次验收

先做练习：如果 `training-result.json` 已产生，但没有 `reload-result.json`，你会允许切换推理服务吗？提示：检查产物完整性、重载一致性和所请求模型的真实身份。

<details>
<summary>完成后查看解释</summary>

不能仅凭训练阶段结束就判定可交付。应先核对完成状态、匹配的基座版本、适配器配置、文件哈希和新进程重载结果，再进行部署兼容检查与真实接口验收。这些检查分别回答“是否产出了文件”“是否能复用”“是否真的在服务”，不能互相替代。

</details>

| 交付内容 | 推理复用是否需要 | 恢复训练时的区别 |
|---|---|---|
| 基座权重与明确 revision | LoRA 未合并部署时需要 | 相同名称但不同权重版本也可能不等价 |
| `adapter_model.safetensors` | 保存增量参数 | 只有它通常不能恢复优化器进度 |
| `adapter_config.json` | 说明目标层、rank和基座信息 | 配置须与实际训练和加载代码一致 |
| tokenizer、聊天模板和预处理 | 输入必须按相同规则构造 | 规则改变可能使之前的训练目标不再一致 |
| optimizer、调度器、步数与随机状态 | 仅推理一般不需要 | 连续恢复训练时通常需要按训练框架完整保存 |
| 数据版本、划分、评分规则和结果 | 用于审计效果 | 不是可训练权重，却决定成绩能否解释 |

PEFT 的适配器保存文件不包含完整基座，通常仍需原始模型才能加载；详见[官方 checkpoint 格式](https://huggingface.co/docs/peft/v0.17.0/en/developer_guides/checkpoint)。本项目历史脚本保存适配器与运行报告，没有把它实现为可恢复到任意中途 step 的完整训练 checkpoint。

`inference/validate_lora.py` 的 metadata 检查要求训练完成、重载文本一致、rank=8、目标模块为 `q_proj/v_proj`、基座路径匹配及两个适配器文件的哈希相符；后续 runtime 检查还会用 vLLM 辅助代码验证并读取张量。它是该历史部署的具体契约，不是适用于所有模型和所有 LoRA 的通用规则。路径匹配不等于基座内容一致，严谨交付仍需记录基座 revision 或权重校验信息。

## 8. 如果下一步要做混元微调，需要重新证明什么

目前不能用“修改模型名”代替下面这些工作。按顺序完成，每一行都应有可保留的产物，再安排共享 GPU 的小规模实验。

| 待核对项 | 具体证据 | 常见失败 |
|---|---|---|
| 任务是否真的需要微调 | 固定开发集上的基线错误分类；先排除检索和提示问题 | 用训练掩盖资料缺失或接口错误 |
| 数据与模板 | 固定数据版本；实际模板生成的完整 token、标签掩码和长度审计 | 回答前缀对不上；答案被截断 |
| 模块与量化兼容性 | 当前模型模块名/形状、可训练参数清单、前向与反向冒烟记录 | 目标层没有匹配到；损失无有效标签 |
| 资源预算 | 单实例、长度、微批次、空闲显存与实际峰值记录 | 只算4-bit权重，遗漏激活与优化器 |
| 效果与独立验收 | 相同条件基线、验证规则、冻结后测试与失败样本 | 反复调测试集，或只报告损失下降 |
| 产物和部署 | 基座revision、适配器哈希、新进程重载、服务模型列表与真实请求 | 把训练环境成功当作vLLM部署兼容 |

旧 Qwen LoRA 的基座、矩阵和训练结果不属于 Hunyuan，不能直接挂到当前混元服务。本章不提供已经完成混元微调的权重、分数或显存承诺。

最后提交一条学习记录：`实验目录 → 数据/模型版本 → 预期 → 实际曲线或输出 → 失败与解释 → 保存重载证据 → 尚未证明的能力`。助手跑通示例属于实现证据；你能独立复做、解释一个失败并恢复，才新增相应的学习掌握证据。
