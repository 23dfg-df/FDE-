## 离线交付先找隐含依赖

项目可能在构建、启动或业务期下载包、拉镜像、取权重、加载字体、上报遥测或查远程身份。区分三个阶段，逐项列代码、运行时、包、tokenizer、配置、迁移和样本。目标CPU架构、Python版本、CUDA组合、权限也要记录；Linux轮子不能假定能用于macOS。已有缓存能掩盖缺件，最好在兼容且干净环境重建。没有条件时保留未验证项，不能把个人电脑断网成功说成客户环境已完成交付。

## 摘要用于完整性，不独立提供来源信任

记录文件来源、版本、大小和SHA256，传输后重算能发现损坏与混错版本。若清单和文件一同被替换，普通摘要不证明发布者身份；可信渠道、签名或组织分发流程处理另一层问题。区分原创代码、第三方依赖和模型权重的许可，不能用框架许可替代模型条件。工程清单说明已核对和未核对项，不自行给出合规结论。必要配置只提供示例，真实凭据由接收环境管理。

## 安装要能处理重复执行和中断

先检查目录、空间和版本，在独立位置准备新产物，验证后再切换。失败下载如果直接写正式文件，下次可能把不完整路径当成有效模型。临时文件、摘要与明确状态有助避免这种半成品。数据库迁移前保留备份，记录步骤是否可重试；不是所有命令重复执行都安全。离线流程要说明停止、恢复与旧版保留。日志不包含密钥，错误提示指出缺件而不是无限尝试联网，才能让接收者定位问题。

## 数据不出域要审查所有组件

文档留内网不证明链路没有外发，嵌入、模型API、插件、监测和日志都可能发送内容或元数据。按种类列接收者、存放与保留期限，检查脱敏、最小权限和导出。提示词中的禁止泄露不能代替授权与工具边界。组织特殊约束由责任人确认，再转成可执行验收。学习只用合成材料，不把真实私密文件带进公开包。删除功能也需说明是否覆盖索引、缓存、备份和导出副本，避免含糊承诺。

## 目标条件下逐项验收

静态网页离线打开只证明页面资源齐全，不证明数据库和GPU服务可运行。按产物完整性、依赖加载、服务就绪、业务请求、重启恢复与导出检查，各自记录输入输出。干净环境比反复使用已有缓存有说服力，但若没有就如实标未执行。把失败步骤和缺失条件写入交接单，让下一个人从确定的位置继续。一次交付可先限定一个模型与一种平台，后续平台支持必须增加对应验证，不能只改README列表。

## 把跨平台失败变成明确验收项

假设交付包包含某Python版本的Linux二进制包，目标机使用另一Python小版本或CPU架构，文件存在也可能无法导入。对纯Python依赖和本地扩展分别检查；模型还需核对框架支持与运行内核。准备阶段记录目标平台和包标签，接收阶段先做低成本导入检查，再加载大型权重。出现不匹配时停止继续启动，给出缺少组件的明确清单，避免在离线环境反复尝试下载。复现报告写出实际目标条件，不能只写“支持Linux”。

## 文件摘要检查

```python
from pathlib import Path
import hashlib
path = Path("artifact.zip")
if path.is_file():
    print(hashlib.sha256(path.read_bytes()).hexdigest())
else:
    print("missing artifact.zip")
```

不下载或执行文件；摘要需要与可信清单对照。

## 失败时检查

### 客户机缺依赖

可能原因：开发缓存掩盖缺件

检查：对照清单做干净重建。

### 摘要相同来源可疑

可能原因：清单同样不可信

检查：核对分发渠道。
