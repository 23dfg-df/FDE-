## 先确定你在哪台机器、哪个目录、哪个环境

SSH登录后终端里的127.0.0.1表示服务器自己；本机浏览器的同一地址则表示你的电脑。服务正常但网页连不上，可能只是请求发到了另一台机器。用hostname、pwd和解释器路径建立上下文，再检查服务配置中的监听地址与端口。相对路径依赖工作目录，systemd启动与手动cd启动可能读到不同文件。环境变量也只传给其子进程，修改当前终端并不改变已经运行的服务。排障记录开头写清请求从哪里发出、目标在哪里、预期监听什么，比立刻改代码更有效。

## 进程、线程与协程共享的东西不同

进程通常有独立虚拟地址空间，线程共享所在进程的内存和文件等资源，协程通常在事件循环里协作调度。虚拟内存是地址映射与保护机制，不等于机器真的有无限内存；RSS只是观察实际驻留的一种口径，也不能简单把所有进程RSS相加当唯一总占用。CPU繁忙可能来自计算或忙轮询，任务慢也可能在等待磁盘和网络。上下文切换需要保存与恢复执行状态，切换次数高是否有害需结合吞吐和等待分析。先区分工作在“算”还是在“等”，再决定是否增加并发。

## 端口监听和应用健康是不同层次

端口在监听只能证明某个进程绑定了地址，不能保证模型已加载或数据库可用。Linux可用ss -ltnp查看监听，普通用户可能看不到其他账户进程详情；再从服务所在机器发送健康检查。connection refused常见于目标地址无监听，连接超时可能涉及路由或策略，HTTP 500表示请求已到应用但处理失败。反向代理返回502或504时要查看上游可达性和超时边界。不要一次修改防火墙、端口、应用和模型参数，否则无法知道哪项改变解决了问题。

## IO和文件描述符能解释“明明空闲却很慢”

阻塞IO让当前执行者等待，非阻塞IO表示操作可立即返回“暂不可完成”，多路复用让一个执行者等待多个就绪事件；它们不是同一个术语。文件、套接字、管道通常占用文件描述符，忘记关闭会使长期服务逐渐耗尽资源。目录存在但无法写入，可能是权限、磁盘空间、配额或只读挂载，应分别检查。把大文件一次性读进内存会放大峰值，分块处理则需要控制缓冲和背压。使用临时目录做文件实验，并在finally或上下文退出时清理，避免学习实验污染真实业务目录。

## 日志以请求为线索，不以刷屏量为目标

一条结构化日志包含时间、request_id、步骤、状态与耗时，可以将网页错误、API处理和模型调用关联起来。先找一次失败请求，再沿它经过的组件检查最近的确定成功点。记录异常类型与关键参数范围即可，不把令牌、完整私人文档或密码写入日志。若服务前台运行，可观察终端；用户服务则使用对应服务的日志入口。结束排障要保存问题、证据、根因、修复和验证；仅写“重启好了”会留下未知原因。执行停止命令前核对进程归属，实验室里不能通过批量终止别人的任务来测试猜想。

## Linux上的只读定位顺序

```bash
hostname
pwd
python3 -c "import sys; print(sys.executable)"
ps -u "$(id -u)" -o pid,stat,comm
ss -ltn
df -h .
# 下一步再对自己明确的服务地址运行健康检查
```

Linux环境；macOS可用lsof -iTCP -sTCP:LISTEN代替ss。示例是诊断步骤，未在你的服务器执行。

## 本课只做一个任务

为一次“浏览器无法访问服务”写出并实践三层定位记录。

1. 明确浏览器、SSH终端和服务各在哪台机器。
2. 检查自己的进程和监听地址，再访问健康接口。
3. 记录最后成功层、第一失败层及下一项最小验证。

## 失败时检查

### SSH里curl成功，本机失败

可能原因：回环地址或隧道上下文不同

检查：分别记录请求从哪台机器发出。

### 服务有进程但接口未就绪

可能原因：模型或依赖仍在初始化

检查：同时检查业务就绪状态与启动日志。
